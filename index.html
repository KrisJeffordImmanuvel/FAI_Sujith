🎯 Project Objective & Engineering Scope

Simulation Mode

This web-based tool simulates a college campus water distribution network and applies the Breadth-First Search (BFS) graph traversal algorithm to solve the critical municipal challenge of pipe rupture fault isolation.

Key Engineering Objectives:

  • Rapid Water Loss Mitigation: Pinpoint damaged pipelines and close boundary valves automatically.
  • Localized Interruption: BFS finds the nearest valves that isolate the rupture (fewest hops), so valves further away stay open.
  • Supply Check: A second BFS from the water tower shows which buildings are still connected through open pipes.

📚 BFS Algorithmic Foundations & Mathematical Formulation

How the campus network is modelled as a graph, and what the two BFS passes do (and do not) compute.

1. Graph Representation of Campus Water Distribution Network

The campus water network is modelled as an undirected, unweighted graph:
G = (V, E), where:

  • Vertices (V): The network components, in 4 groups:
    • Vsource = { WT } — Primary elevated water tower.
    • Vjunction = { J1, J2, J3, J4, J5 } — Distribution manifolds.
    • Vvalve = { V1, V2, V3, V4 } — Isolation valves (one on each building branch).
    • Vbuilding = { Hostel, Laboratory, Canteen, Academic, Library } — Consumer buildings.
  • Edges (E): The 17 pipes, each connecting a pair of nodes (u, v). Each pipe also stores a length (m), diameter (mm) and design flow (L/min) for display and the report, but BFS ignores these values: every pipe counts as exactly one hop.

2. What BFS Finds Here (and What It Does Not)

BFS is unweighted: it counts hops (pipes crossed), not metres, litres or bar.

What it finds:

BFS finds the nearest valves that isolate the rupture (fewest hops). It explores outwards from both ends of the broken pipe one level at a time and stops each branch at the first valve it meets, so a valve further out along the same branch is never closed. Then it keeps only the valves on the water-tower side: no water reaches the burst through the others, so closing them would be unnecessary. If the search reaches the water tower without passing a valve, no valve can isolate that pipe and none is closed.

What it does not do:

  • It does not use pipe length, diameter or flow, so "nearest" means fewest pipes, not shortest distance.
  • It cannot isolate a pipe that has no valve between it and the water tower. In this network the valves sit only on the building branches, so a burst on the tower pipe, a junction pipe or a loop pipe cannot be stopped with valves: the leak continues until the pipe is repaired (or the tower is shut).
  • It does not simulate flow rates or water pressure. "Supplied" only means a building is still connected to the water tower by open pipes.

Time Complexity: O(V + E) | Space Complexity: O(V)

3. Step 2 – First BFS: Find the Valves to Close

When pipe e = (ufault, vfault) ruptures, multi-source BFS begins simultaneously from both endpoints:

Algorithm FirstBFS(u_fault, v_fault, G): Input: Fault endpoints u_fault, v_fault, Network Graph G = (V, E) Output: Valves to close C (empty if the pipe cannot be isolated) Initialize Queue Q ← Empty Initialize Visited Set V_visited ← { u_fault, v_fault } Initialize Boundary Set B ← Empty For each endpoint ep in { u_fault, v_fault }: If Node_Type(ep) == 'valve': B.add(ep) Else: Q.enqueue(ep) If ep == WT: Return ∅ // burst touches the tower: cannot isolate While Q is not empty: curr ← Q.dequeue() For each neighbor nbr in Adjacent_Nodes(curr): If (curr, nbr) == (u_fault, v_fault) or (curr, nbr) == (v_fault, u_fault): Continue // Skip damaged pipe If nbr not in V_visited: V_visited.add(nbr) If Node_Type(nbr) == 'valve': B.add(nbr) // Boundary valve reached! // STOP branch expansion: Do NOT enqueue nbr Else If nbr == WT: Return ∅ // reached the tower without a valve: cannot isolate Else: Q.enqueue(nbr) // Continue level expansion // Keep only valves on the water-tower side (upstream): // a valve is upstream if WT can reach it without entering V_visited Region ← V_visited minus valves C ← { b in B : Reachable(WT, b) avoiding Region and the damaged pipe } Return C

4. Step 4 – Second BFS: Check Supply

With the boundary valves B closed (Step 3) and the broken pipe removed, BFS starts at the Water Tower and marks every node it can still reach:

Algorithm SecondBFS(Water_Tower, Closed_Valves, G): Input: Water Tower 'WT', Set of closed valves B, Graph G Output: Reachable_Buildings, Affected_Buildings Initialize Queue Q ← Empty Initialize Reachable Set R ← { WT } Q.enqueue(WT) While Q is not empty: curr ← Q.dequeue() If curr in Closed_Valves: Continue // Closed valve blocks downstream flow For each neighbor nbr in Adjacent_Nodes(curr): If (curr, nbr) is faulty pipe: Continue If nbr in Closed_Valves: R.add(nbr) // Flow reaches valve inlet, but stops Continue If nbr not in R: R.add(nbr) Q.enqueue(nbr) Operational_Buildings ← All buildings in R Affected_Buildings ← All buildings NOT in R Return Operational_Buildings, Affected_Buildings

🛡️ Simulation Modeling Disclaimer

This software is an AI algorithmic micro-project developed for academic evaluation purposes. It models the network only as a graph of connections and uses Breadth-First Search to decide which valves to close and which buildings stay connected. It does not simulate flow rates or water pressure; pipe sizes, flows and the water-saved estimate in the report are illustrative figures. No physical sensors or hardware controllers are required.
